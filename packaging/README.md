# Packaging

- `windows/kitab.rc` embeds the app icon (id 1, used by GPUI for the window and taskbar) and the document icons (101 PDF, 102 EPUB, 103 Markdown, 104 MOBI, 105 FB2, 106 CBZ, 107 XPS, 108 TXT) in `kitab.exe` (`crates/kitab/build.rs`). File associations point at them as `kitab.exe,-<id>`. Kitab writes them per user from Settings › Reading › Default app (`kitab-os::assoc`); the MSI (Phase 10) writes the same keys.
- `macos/Info.plist` declares the document types and icons (`Kitab.icns`, `doc-*.icns`), with `LSHandlerRank` Alternate. `@VERSION@` is filled from the workspace version at bundle time.
- `linux/dev.t21.kitab.desktop`, `linux/dev.t21.kitab.xml` (shared-mime-info) and `linux/icons/hicolor/` go to `/usr/share/applications`, `/usr/share/mime/packages` and `/usr/share/icons`.

All icons are generated by `tools/make_icons.py`; edit the script, not the files.

## Thumbnails

Every system uses `kitab --thumbnail` (crate `kitab-thumb`): page 1 of a document, or a page preview of Markdown and text. It runs as its own short process and exits before any window code.

- Linux: `linux/dev.t21.kitab.thumbnailer` goes to `/usr/share/thumbnailers/`. GNOME Files, Nemo, Caja and Thunar (tumbler) then call `kitab --thumbnail -s SIZE IN OUT.png`. KDE Dolphin uses its own plugins.
- Windows: `kitab_shell.dll` (crate `kitab-shell`) is the Explorer thumbnail provider. It pipes the file to `kitab.exe --thumbnail --stdin EXT --bgra` next to it, so MuPDF ships once and a bad file can't crash Explorer.
- macOS: a Quick Look thumbnail extension, with the macOS build.

## Linux packages and Flatpak

`tools/package.py` lays the Linux files out once (`/usr/bin`, `/usr/share/...`, with `linux/dev.t21.kitab.metainfo.xml` for software centres) and builds the `.tar.gz`, `.deb`, `.rpm` and `.AppImage` from them. `flatpak/dev.t21.kitab.yml` builds the Flatpak from source, offline; `flatpak/generate-sources.sh` writes the crate list it needs.

## Microsoft Store (MSIX)

`tools/package_msix.py <version>` builds `dist/Kitab_<version>_x64.msix`, the file uploaded in Partner Center. The release workflow builds it too and keeps it as the `kitab-msstore` workflow artifact, not as a release download. The package is unsigned because the Store signs it after certification.

- `windows/msix/AppxManifest.xml` is the template. Its `Identity` (`TriptoAfsin.KitabReader`, `CN=83EC5113-…`) and `PublisherDisplayName` are the values Partner Center reserved (Product management › Product identity), and they must match exactly. The script fills in the version (`x.y.z.0`; the Store keeps the fourth number) and writes one file type association per entry of `FILE_TYPES` in `kitab-os/src/assoc.rs`, each with its document icon, Print (where `assoc.rs` adds it) and `kitab_shell.dll` as the thumbnail handler. Packaged apps can't write these to the registry.
- The tile and Store icons are drawn from `assets/brand/kitab-1024.png` at every scale and target size, and indexed in `resources.pri` by `makepri`. Both `makepri` and `makeappx` come from the Windows SDK.
- When packaged, `kitab_os::packaged()` is true. `update::managed_by()` then says the Microsoft Store, so Kitab doesn't ask GitHub for updates, and Settings › File types points to Default apps instead of writing the registry.
- To try it without signing, turn on Developer Mode, then run `Add-AppxPackage -Register dist\msix\AppxManifest.xml`. `Get-AppxPackage *KitabReader* | Remove-AppxPackage` removes it.

## Command line

The `kitab` command (crate `kitab-cli`) lets people, scripts and AI agents use Kitab from a terminal: `kitab markdown report.pdf`, `kitab merge a.pdf b.pdf -o both.pdf`, `kitab --help`.

- Windows: the windowed `kitab.exe` can't print to a terminal, so the console `kitab-cli.exe` ships as `bin\kitab.exe` next to it (`tools/build_release.py` builds it with the same static C runtime; `tools/package.py` lays it out in `dist/Kitab/bin/` and the portable zip). The installer's task "Add the kitab command to the terminal", on by default, adds `{app}\bin` to the user PATH (`HKCU\Environment\Path`) and the uninstaller takes exactly that entry off again. Settings › Advanced › Command line turns the same entry on or off later (`kitab-os/src/cli_path.rs`) and tells running programs the environment changed, so new terminals see it.
- Microsoft Store: packaged apps can't change PATH. The manifest's second application, `KitabCli` (`bin\kitab.exe`, no Start menu entry), declares the app execution alias `kitab.exe` as a console program, so `kitab` works in any terminal. Settings says the Store installs it and shows no switch.
- macOS and Linux: the main `kitab` binary runs the commands itself when its first argument is a command (`crates/kitab/src/main.rs`). The Linux packages install it as `/usr/bin/kitab` (the `.tar.gz`'s `install.sh` as `~/.local/bin/kitab`); with the Flatpak it is `flatpak run dev.t21.kitab <command>`. On macOS, Settings › Advanced › Command line links `~/.local/bin/kitab` to `Kitab.app/Contents/MacOS/kitab`; that folder must be on PATH.
